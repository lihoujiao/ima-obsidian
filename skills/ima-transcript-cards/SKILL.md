# 转写 → 结构化纪要卡片

## 这个 skill 解决什么

**为什么叫「拉取入库前」**：每次拉 IMA 增量之前，先把上一批已落盘的转写消化成卡片——
不然转写越堆越多，全是读不动的原始文本。**先清库存，再进货**。

IMA（和各类录音设备）拉回来的语音转写是**一坨口语连读文本**：无说话人标签、无分段逻辑、无字段。
本 skill 把它变成一张**能查、能引、能挂项目**的纪要卡片，字段结构固定为：

1. **记录信息**：转写地址、时间、时长、主诉人、对话人、旁听人
2. **主题清单**：这场谈到的几件事，各自一句话结论 + 关键数字
3. **待办清单**：谁在什么时候前做什么，附原话依据

**分工铁律**：脚本只做机械活（扫描/去重/正则提取候选/渲染落盘），
语义活（认人、定主题、抓待办、写判断）由你——执行时的模型——完成。
**不要在脚本里加"猜内容"的逻辑**，猜错比不猜更糟。

## 硬规则

| 编号 | 规则 |
| --- | --- |
| R1 | **一条转写 = 一张卡**。不按主题拆多张，哪怕 60 分钟聊了五件事，五件事进同一张卡的「主题」表 |
| R2 | **缺字段必须问，不许编**。地址、时间、时长、主诉人、对话人、旁听人，转写里读不到就当场问；用户答"不知道"才能写「未记录」 |
| R3 | **逐条问**：处理一批时，一条的所有缺失字段**合并成一次提问**，答完立刻渲染落盘，再进下一条。不要一条问三次 |
| R4 | **主诉人 = 这场谈话在谈谁的事**（谁在提需求 / 这场是为谁开的）。不是"说话最多的人"，不是"发起邀约的人" |
| R5 | **原始转写一个字都不改**。只新增卡片文件，不回写、不移动、不重命名源文件 |
| R6 | **落点**：有项目归属 → 落该项目目录，沿用 `YYYY.MM.DD_{类型}_{标题}.md`；无项目归属 → 留在源文件同目录（`01-Raw/1-我的文章/1-1来自IMA/...`） |
| R7 | **待办只写卡内**。不推企微待办、不写业务台账，除非用户当次明确要求 |
| R8 | **人名不做推断性补全**。转写里只有「杭总」时，要么从库内人物档案确认全名，要么问用户；确认不了写「杭总（全名待核）」，绝不自己配一个全名 |
| R9 | **拉取后按时间正序逐条询问**。一批待处理条目先用扫描出的 `date_guess`（拿不到回退 IMA 落点日期目录）**升序排序——最旧在前，最新在后**，再逐条问。不按 `scan` 返回的默认顺序问，也不挑着问；问完最旧的再进下一条 |
| R10 | **时间/时长优先自取，再问用户**。转写正文没时间码 ≠ 拿不到时间。先走两条通道：① IMA「导出」勾选「显示时间戳 / 时间轴」，或导出 **SRT/VTT** 字幕（自带时间轴，脚本 `TS_RE` 算时长、`DATE_FULL_RE` 解析日期+时刻）；② IMA 条目 / 文件夹下方显示的时间信息。两条都推不出，才按 R2 问用户；别一上来就让用户报时长 |

## 字段口径

| 字段 | 从哪来 | 读不到怎么办 |
| --- | --- | --- |
| 转写地址 | 脚本自动（`source_rel` + `ima_url`） | — |
| 时间（日期+时刻） | ① 转写首行常有「2026年10月15日 15:08」② 导出 SRT/VTT 或勾「显示时间戳」后自带时间轴 ③ IMA 条目/文件夹下方时间 ④ 退而用 IMA 落点的日期目录 | 全推不出 → 问时刻 |
| 时长 | ① 转写内时间码最大值（本地录音 txt 有，IMA 转写常常没有）② SRT/VTT 导出自带时间轴 ③ IMA 条目下方「音频 \| MM:SS」即时长 | 都没有 → **必问**，用户报大概也行（"大概四十分钟"→ 写「约 40 分钟」） |
| 地点 | 转写里显式说「地址/地点/位于」+ 地名词（路/街/镇/园区/酒店/餐厅…） | **必问**。只提到"胥口""太仓"不足以定地址，要问具体场所 |
| 主诉人 | 全文在谈谁的事 → 一个名字 | **必问**。给 2–3 个候选让用户挑，别开放式问 |
| 对话人 | 转写里明确发声的其他人 | **必问**（顺手确认，用户常一次答全） |
| 旁听人 | 在场但基本不发声的人 | **必问**，没有就记「无」（空列表） |

> ⚠️ 「地址」两层含义都收：**转写地址**（文件路径 + IMA 回链）自动填；**会面地点**问用户。两个字段都在卡片里。

## 执行流程

### 第 1 步：扫描

```bash
PY="C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
S="C:/Users/Administrator/.workbuddy/skills/IMA拉取入库前/scripts/ttm.py"

"$PY" "$S" scan --vault "D:/OB" --json "D:/OB/01-Raw/.workbuddy/tmp/ttm_scan.json"
```

输出：`counts.pending`（待处理）+ `pending[]`（每条带 `body` 清洗后正文）。
`skipped` 里是已结构化 / 正文过短 / 昭屹标记跳过的条目，不用管。

单条处理加 `--file 关键词`：`--file 文旅项目`。

**去重靠卡片的 `source_transcript` 字段**，不靠改源文件——源文件保持原样。

**跳过清单**：授课、分享、纯方法论讲解这类**没有洽谈内容**的转写不建卡。写进 `D:/OB/.workbuddy/ttm_skip.json`：

```json
{ "01-Raw/1-我的文章/1-1来自IMA/2026年44周/2026/11/01周日/xxx.md": "授课分享，非洽谈场" }
```

键＝相对 vault 的路径（`scan` 输出的 `source_rel`），值＝跳过原因。加进去后 scan 报 `昭屹标记跳过（原因）`，不再提示。**源文件仍一字不改。**

### 第 2 步：逐条处理（核心）

**先排序**：把 `scan` 给出的 `pending[]` 按 `date_guess`（拿不到回退落点日期目录）**升序排好**（最旧在前，最新在后），再开始逐条问。这是硬规则 R9。

对每条 `pending`（按排好的顺序）：

1. **读 `body` 全文**（不要只读开头，主题和待办常在后面）
2. 在心里定这几件事：
   - 这场是**会议 / 接触 / 电话**（见下方判定）
   - **主诉人**是谁（谈谁的事）
   - **主题**有哪几个（宁可 3 条实的，不要 8 条虚的）
   - **待办**有哪几条（带原话）
   - **项目归属**候选（`project_candidates` 仅供参考，你还要看内容）
3. **列出缺失字段，一次问完**（话术见下）
4. 用户答完 → 拼 `card.json` → `render` 落盘
5. 报一句结果，进下一条

### 第 3 步：提问话术（照这个格式，别自由发挥）

```
第 1/5 条 · 文旅项目投资与运营讨论（2,621 字）

读出来的：
· 日期 2026-10-31
· 主诉人 杭广发（在谈他的园区地块和米粉配送半径）
· 对话人 殷昌志、李后铰
· 主题 4 个：地块租金 / 80 公里配送半径 / 运费 60 元红线 / 卤味猪肉价
· 待办 4 条
· 归属判为 5-1-亦芙德 → 落 5-1-0-知识输入/

缺 3 项，你补一下：
1️⃣ 时长？（先看 IMA 导出/条目下方的时长或 SRT/VTT 时间轴；确实没有再估个数）
2️⃣ 地点？（原文提到"胥口"，是在那边看的厂房吗）
3️⃣ 旁听人？（有在场没说话的就说名字，没有回"无"）
```

要点：**先把读出来的摊开**（让用户知道你真的读了），**再把缺的编号列出**，
有候选就给候选（"是在胥口吗"好过"地点在哪"），最后一行给归属判断让他否。

### 第 4 步：渲染落盘

先写 `card.json`（路径建议 `D:/OB/01-Raw/.workbuddy/tmp/ttm_card.json`），再：

```bash
# 先预览，确认排版无误
"$PY" "$S" render --card "D:/OB/01-Raw/.workbuddy/tmp/ttm_card.json" --dry-run

# 确认后落盘
"$PY" "$S" render --card "D:/OB/01-Raw/.workbuddy/tmp/ttm_card.json"
```

`card.json` 结构（必填项缺失脚本会拒绝写文件并回 `missing` 列表）：

```json
{

  "type": "接触纪要",
  "target_dir": "01-Raw/5-项目一手资料/5-1-亦芙德/5-1-0-知识输入",
  "record_date": "2026-10-31",
  "record_time": "15:08",
  "duration": "约 42 分钟",
  "location": "上海市闵行区某咖啡店",
  "subject_person": "杭广发",
  "subject_note": "谈的是他的文旅园区地块与米粉厂配送半径",
  "participants": ["殷昌志", "李后铰"],
  "observers": [],
  "title": "杭广发（文旅园区地块与米粉配送半径）",
  "project": "5-1-亦芙德",
  "summary": "一句话结论，可直接下判断，不要复述对话",
  "topics": [
    {"title": "米粉厂配送半径", "point": "以米厂为圆心半径 80 公里，超圈每单加 2 元", "numbers": "80 公里"}
  ],
  "todos": [
    {"task": "画 80 公里覆盖圈", "owner": "李后铰", "due": "2026-11-05", "quote": "我现在就把它画出来"}
  ],
  "numbers": [{"item": "运费上限", "value": "60 元/吨", "note": "硬红线"}],
  "doubts": ["「100 多块一天」是整层日租还是每平米月租，量级差 30 倍"],
  "judgment": "判断段：这一场值什么、下一步押哪",

```

### 第 5 步：收尾

一条落盘后报：

```

   主题 4 · 待办 4
```

全部跑完给一张汇总表：条数、落点、主题数、待办数、跳过的原因。

## 判定规则

### 纪要类型

| 类型 | 特征 |
| --- | --- |
| **会议纪要** | 正式洽谈、会议室/办公室、多方在场、有明确议题推进 |
| **接触纪要** | 饭桌、走动、看样、车程、闲聊里夹生意（最常见） |
| **电话纪要** | 电话 / 微信语音，单对单，时长几分钟到半小时 |

拿不准时按**信息形态**判，不按录音时长：有桌有酒有走动 → 接触纪要。

### 项目归属

按优先级：

1. `project_candidates` 命中（库内项目名/人物档案名在正文出现）
2. 主诉人已在某项目下有档案 → 归该项目（`5-N-...-姓名档案/`）
3. 内容涉及的产业与某项目一致（亦芙德=冷链/粮油/卤味/食堂渠道；奚强=农贸市场；递道鲜=汤料包）
4. **都不符 → 留在源文件同目录**（`target_dir` 填 `source_rel` 的父目录）

判不了就**在提问里带上归属，让用户一句否掉**，不要开放式问"这归哪个项目"。

### 落点目录

- 知识输入类（行业信息、宣讲、外部交流）→ `5-N-0-知识输入/`
- 与某个具体的人相关（买方/卖方/资方）→ `5-N-M-K-姓名档案/`
- 无归属 → 源文件所在目录

## 几个必须知道的坑

1. **IMA 同步的转写正文没时间码，但时间/时长取得到** → ① 导出时勾「显示时间戳/时间轴」或导出 SRT/VTT（脚本 `TS_RE` 算时长、`DATE_FULL_RE` 解析日期+时刻）；② IMA 条目 / 文件夹下方显示的时间信息。两条都推不出，才让用户报（大概也行）。本地录音 txt（`2026.10.15_录音_xxx.txt`）同样带 `02:14` 式时间码。⚠️ 备注：IMA 条目下方「音频 | 20:52」这类是**时长**（音频长度），不是时刻——时长用它、时刻走导出/文件夹时间。
2. **转写没有分轨**（"未分轨、非逐字稿"）→ 谁说的分不清。写待办负责人时只写**明确被指派的人**，其余写「待定」，不要按语气猜。
3. **「某总」不能当人名**。`address_candidates` 里的「杭总 / 修总 / 李工」只是**称呼候选**，卡片 `主诉人` 字段要填全名。全名从库内人物档案拿，拿不到就问——这是 `MEMORY.md` 的铁律（「刘欣平」教训）。
4. **地点正则不能用裸「在」**：口语「在上海成立一个运营中心」会被误判成地址。已收紧为「地址/地点/位于 + 地名词尾」。
5. **人名候选要过姓氏白名单 + 频次 ≥2**：否则「人工 / 加工 / 老总 / 施工」全被当人名。低置信候选在 `address_low_conf` 里，可参考不可直接采信。
6. **重新同步 IMA 会覆盖源转写**，所以卡片必须是**独立文件**，绝不往源文件里塞结构化区块。
7. **同一场录音可能被拆成多个 IMA 条目**（按录制分段）。落卡时先看 `date_guess` + `subject_person` 是否撞车，撞了就在提问里说明"这条疑似与 XX 同场，要不要合成一张"。
8. **`title` 字段的括号里放主题，不是放类型**：`杭广发（文旅园区地块与米粉配送半径）`，不要写成 `杭广发（接触纪要）`——类型已经在文件名中间了。

## 卡片长什么样

文件名：`2026.10.31_接触纪要_杭广发（文旅园区地块与米粉配送半径）.md`

正文结构（脚本固定渲染）：

```
frontmatter：类型/记录日期/记录时间/时长/地点/主诉人/对话人/旁听人/主题/待办数/项目/source_transcript/ima_url/tags
# 接触纪要 · 杭广发（…）
> 场合 / 在场 / 原始转写链接
## 一句话结论
## 一、记录信息（表：转写地址·时间·时长·地点·主诉人·对话人·旁听人·转写）
## 二、主题（表：#·主题·要点·关键数字）
## 三、待办（表：#·待办·负责人·截止·依据原话）
## 四、关键数字（表，有才出现）
## 五、存疑与待核（有才出现）
## 六、判断（有才出现）
```

后三段（数字/存疑/判断）是**增值**，跟库里现有 `_接触纪要_` 模板对齐；
用户若只要三块，删这三段不影响前两块。

链接一律**相对路径**（全库标准，不用 wikilink）。
